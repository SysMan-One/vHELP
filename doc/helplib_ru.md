
# VHELP -- выдача сведений из библиотеки справки

Вызывает справочную службу для выдачи сведений о теме, хранящейся
в библиотеке справки.

Формат:

```
VHELP [тема [подтема ...]] [/квалификаторы]
```

На запрос \`Topic?\` наберите имя темы, пустую строку для подъёма на
уровень вверх или EXIT для выхода из службы.

Ключ, содержащий пробел, набирается либо как несколько слов подряд,
либо в кавычках -- служба сама подбирает самый длинный подходящий
ключ:

```
$ vhelp help vhelptran формат исходного текста
$ vhelp help vhelptran "формат исходного текста"
```

Тема может нести шаблон, и тогда одна за другой выдаются все подтемы,
чьи имена ему отвечают: * заменяет любую последовательность знаков,
% и ? равно -- один любой знак.

```
$ vhelp help vhelptran /*
$ vhelp help vhelptran /?DENT
```

Квалификатор пишется через слэш либо через удвоенный дефис:
/WIDTH=80 и --WIDTH=80 -- одно и то же. Одиночный дефис приставкой
квалификатора не является, поэтому -LIST есть тема; единственное
исключение -- запрос синтаксиса команды, который распознаётся во
всех обычных написаниях.

Ключ может называться в точности так же, как квалификатор самой
утилиты -- /LIST является и тем и другим, -- и квалификатор
побеждает. Одиночное \`--\` завершает квалификаторы, так что до такого
ключа всё же можно добраться:

```
$ vhelp -- help vhelp /list
```

## ПАРАМЕТРЫ

### тема

Имя темы, о которой требуются сведения. Вместо целого ключа
допускается его однозначное начальное сокращение; неоднозначное
сокращение трактуется так, как если бы к нему приписали звёздочку.

### подтема

Имя подтемы названной перед ней темы. В одной команде можно назвать
сколько угодно уровней -- вплоть до глубины вложенности библиотеки.

## /LIBRARY -- выбор библиотеки или пути поиска

```
/LIBRARY=спецификация
/LIBRARY=элемент[:элемент ...]
```

Значение, называющее одну библиотеку, привязывает запуск к ней:
отвечает она либо не отвечает никто. О несуществующем имени
сообщается, а не подставляется тихо другая библиотека.

Значение, называющее каталог, либо список элементов через двоеточие,
есть путь поиска -- и он весь. Квалификатор есть указание для этого
запуска и исполняется буквально, поэтому больше ничего не
просматривается, включая установленные библиотеки.

При отсутствии квалификатора путь поиска составляется из

```
$HELP_LIBRARY           библиотека, каталог или список того и другого
$HOME/.help             личные библиотеки пользователя
<установка>/<язык>      перевод руководства, когда локаль называет
                        язык и такой каталог есть
каталог установки       библиотеки, с которыми изделие установлено
рядом с образом         они же, найденные относительно работающей
                        программы, поэтому перенесённое или
                        размещённое в другом месте дерево отвечает
```

Язык -- первая составляющая LC_MESSAGES, LC_ALL или LANG, смотря что
задано раньше: ru из ru_RU.UTF-8. Перевод определяет те же темы, что и
оригинал, поэтому им не место рядом на одном пути: один лишь закрывал
бы другого, а какой из них нужен -- вопрос, на который может ответить
только пользователь.

Переменная окружения есть постоянное предпочтение, а не указание,
поэтому она возглавляет путь по умолчанию, а не заменяет его.

именно в этом порядке, и он же есть порядок старшинства: тема,
определённая библиотекой раньше по пути, закрывает определённую
позже -- так же, как команда, найденная раньше по PATH. Что и чем
закрыто, показывает /CATALOG.

Элемент пути, являющийся каталогом, просматривается на предмет файлов
типа .hlb в порядке сортировки имён. Элемент, оканчивающийся
многоточием, просматривается на всю глубину дерева -- по образцу
[dir...] в спецификации файла VMS:

```
$ vhelp /LIBRARY=/opt/pkg/help/... тема
```

В ссылку на каталог обход не заходит: именно так дерево и начинает
содержать само себя.

## /WIDTH -- ширина страницы

```
/WIDTH=n
```

Задаёт ширину страницы в знаках, отменяя ширину, сообщаемую
драйвером терминала. Значение ограничивается диапазоном от 32 до
512.

Ширина столбца в блоке подтем считается в знаках, а не в байтах,
поэтому кириллический ключ занимает ровно свой столбец.

## /PAGE -- останавливаться на границе страницы

Квалификатор негируемый: /NOPAGE подавляет остановку в конце каждой
страницы, /PAGE требует её явно.

Постраничная выдача действует только когда вывод направлен на
терминал, поэтому перенаправленный запуск не ждёт нажатия клавиши
при любой из форм.

В конце страницы HELP спрашивает, что делать дальше:

- RETURN - показать следующую страницу;
- Q и RETURN - пропустить остаток темы. HELP снова выводит список
  подтем и спрашивает подтему того же уровня;
- Ctrl-D - сразу выйти из HELP.

## /PROMPT -- входить в диалог

Квалификатор негируемый: /NOPROMPT выдаёт названную в команде тему и
завершается, /PROMPT требует диалога явно.

В диалог утилита входит только когда вывод направлен на терминал.

## /LIST -- перечень тем

Перечисляет все ключи библиотеки, по одному в строке, с отступом по
уровню вложенности, а перед ними -- шапку: идентификацию, время
создания и то, чем и из чего библиотека изготовлена.

## /CATALOG -- перечень пути поиска и его библиотек

Выдаёт путь поиска, используемый кэш каталога, все найденные
библиотеки и темы, за которые каждая отвечает. Тема, за которую уже
отвечает библиотека раньше по пути, помечается как закрытая.

## /CACHE -- использование кэша каталога

Квалификатор негируемый, и /CACHE действует по умолчанию. Каталог
пути поиска -- какая библиотека отвечает за какую тему -- хранится в
кэше, чтобы не открывать все библиотеки при каждом запуске. /NOCACHE
строит каталог заново и ничего не записывает.

Кэш размещается в первом из перечисленного, что удаётся получить:

```
$HELP_CACHE             названо прямо
$XDG_CACHE_HOME/help/   обычное место
$HOME/.cache/help/      когда XDG_CACHE_HOME не определена
/tmp/help-<uid>/        когда домашнего каталога нет вовсе
```

Кэш сверяется со временем изменения и размером каждого элемента пути
поиска, включая каталоги, поэтому добавленная, изменённая или удалённая
библиотека замечается без открытия чего бы то ни было. Кэш, который
не сходится, не читается или не является личным файлом этого
пользователя, отбрасывается и строится заново, а не чинится --
удалять его вручную никогда не требуется и никогда не вредно.

Последний из перечисленных каталогов доступен на запись кому угодно,
поэтому кэш там считается враждебным. Каталог должен принадлежать
этому пользователю и быть закрыт для прочих; он проверяется один раз,
а всё дальнейшее делается относительно его дескриптора, а не имени.
Имя разрешалось бы заново при каждом обращении, и в промежутке между
двумя разрешениями его можно заставить означать другое -- дескриптор
заставить нельзя. Поэтому наличие бита sticky у общего каталога роли
не играет: ему ничего и не доверяется.

## /SYSCACHE -- построение каталога, общего для всех пользователей

Просматривает путь поиска и записывает каталог, который читает каждый
пользователь системы, в каталог, заданный при конфигурации изделия.

```
$ vhelp /SYSCACHE /LIBRARY=/usr/local/share/help
%HELP-I-SYSCACHE, /var/cache/help/catalog.idx written, 93 topics out of 31 files
```

Каталог -- тот, с которым изделие сконфигурировано, если только
HELP_SYSCACHE не называет другой; ту же переменную читает и обычный
запуск, поэтому записанный в стороне каталог там же и находится.

Это административное действие: оно требует права записи в тот
каталог, которого обычный запуск не имеет и не просит. Установка
изделия выполняет его для своих библиотек; повторять его следует
всякий раз, когда в системный каталог добавлены библиотеки.

Общий каталог есть хранилище уже открытых библиотек, а не кэш
какого-то одного пути поиска, поэтому пользователь с другим путём
всё равно берёт из него те библиотеки, которые там есть. Каждая
сверяется с файловой системой в момент взятия, ровно как в личном
кэше, так что устаревшая запись пропускается, а не принимается на
веру.

Общий каталог, доступный на запись кому угодно, отвергается: иначе
это был бы способ направить всех пользователей системы к библиотеке
по чужому выбору.

## /HELP -- выдача синтаксиса команды

Выдаёт краткое описание синтаксиса команды и завершается, вовсе не
читая библиотеку. Пригодно, когда до самой библиотеки не добраться.

Запрос распознаётся во всех обычных написаниях -- /HELP, /H, -help,
--help, -h, -- но только в форме со слэшем или с дефисом. Одиночное
HELP есть имя темы, и такая тема в этой библиотеке определена.

## ПРИМЕРЫ

```
$ vhelp submit
$ vhelp submit /after
$ vhelp sub*
$ vhelp /library=mylib.hlb тема подтема
$ vhelp /list /nopage | wc -l
```

# VHELPTRAN -- изготовление библиотеки справки

Транслирует один или несколько файлов на Markdown в библиотеку
справки. VHELPTRAN для этой службы -- то же, что LIBRARY/HELP/CREATE
для OpenVMS.

Формат:

```
VHELPTRAN файл.md [файл.md ...] [/квалификаторы]
VHELPTRAN /EXTRACT файл.hlb [/KEY=путь] [/OUTPUT=файл.md]
```

Каждый входной файл вносит свои темы в одну библиотеку, названную
квалификатором /OUTPUT.

## ФОРМАТ ИСХОДНОГО ТЕКСТА

Исходный текст -- обычный файл на Markdown. Его заголовки становятся
ключами библиотеки, а всё, что между ними, -- текстом темы; ничего
другого в файле структурного смысла не несёт.

```
# SUBMIT                ->      1 SUBMIT
## /AFTER               ->      2 /AFTER
### ПРИМЕРЫ             ->      3 ПРИМЕРЫ
```

В одной команде можно назвать несколько исходных текстов; каждый
вносит свои темы в одну библиотеку.

### ЗАГОЛОВКИ -- как получается ключ

Заголовок -- это от одного до девяти знаков решётки, за которыми
следует пробел. Число знаков задаёт уровень вложенности темы;
закрывающая цепочка решёток, если она есть, отбрасывается.

Ключом служит текст заголовка с убранной разметкой, обрезанный по
первому пояснительному разделителю, очищенный от краевых пробелов,
с внутренними цепочками пробелов, сведёнными к одному, и переведённый
в верхний регистр. Разделители такие:

```
" - "     " -- "     " : "     длинное тире     короткое тире
```

поэтому заголовок

```
## /AFTER -- задержать задание до указанного времени
```

даёт ключ /AFTER, а сама строка остаётся читаемой в исходном тексте.
Когда разделителя нет, ключом становится весь заголовок, вместе с
пробелами: заголовок

```
## Формат исходного текста
```

даёт ключ ФОРМАТ ИСХОДНОГО ТЕКСТА, который называется либо
несколькими словами подряд, либо в кавычках.

Регистр приводится и для латиницы, и для кириллицы, в кодировке
UTF-8, поэтому русский ключ ищется независимо от того, каким
регистром его набрали.

Когда по правилам получается не тот ключ, который нужен, его задают
прямо:

```
<!-- key: /AFTER -->
## Совершенно любой заголовок
```

### ТЕКСТ -- что происходит с телом темы

Тело темы преобразуется в простой текст. Таблица говорит, во что
обращается каждая конструкция; всё, что в ней не названо, переносится
без изменений.

```
огороженный блок, ``` или ~~~   переносится дословно и сдвигается
                                на две позиции вправо; сами строки
                                ограждения исчезают, а внутри блока
                                ничего не разбирается
**жирный**  __жирный__          маркеры убираются
`код`                           обратные кавычки убираются, текст
                                между ними берётся как есть
                                (\x там и остаётся \x)
[текст](url)                    обращается в: текст
![замена](url)                  обращается в: замена
- пункт   * пункт   + пункт     маркер списка обращается в букву o
> цитата                        маркер убирается
\x                              обращается в: x
| а | б |                       переносится как есть
```

Отступ в начале строки сохраняется, поэтому вложенные списки и
отбитые примеры сохраняют свой вид. Пробелы в конце строки
отбрасываются. Строка, от которой после преобразования ничего не
остаётся -- такова горизонтальная черта, -- становится пустой.

Пустые строки внутри темы сохраняются, а ведущие и замыкающие тему
отбрасываются, поэтому выдача никогда не начинается и не кончается
пустотой.

**Текст никогда не переформатируется по ширине.** Он выдаётся ровно
так, как написан, с отступом в две позиции на каждый уровень
вложенности плюс две. У темы третьего уровня на восьмидесятизначном
терминале остаётся шестьдесят две позиции, поэтому исходный текст
разумно держать в пределах примерно шестидесяти пяти колонок.

Текст, стоящий перед первым заголовком, не принадлежит ни одной теме
и отбрасывается с выдачей диагностики.

### ДИРЕКТИВЫ

Распознаются три директивы, каждая записывается как комментарий HTML
и занимает отдельную строку:

```
<!-- key: /AFTER -->      ключ следующей за ней темы
<!-- ident: X-01 -->      идентификация библиотеки
<!-- ignore -->           открывает область, не входящую в библиотеку
<!-- resume -->           закрывает её
```

Внутри исключённой области не разбирается ничего -- в том числе
заголовки, -- поэтому документ, служащий одновременно руководством и
исходным текстом справки, может держать свою преамбулу вне
библиотеки.

Идентификация, заданная квалификатором /IDENT, старше записанной
здесь: квалификатор есть указание для конкретного запуска, а
директива -- свойство файла, который кто угодно может оттранслировать
для своих целей.

Внутри огороженного блока директива -- обычный текст, чем здесь и
пользуются, чтобы показать все четыре.

### ПРЕДЕЛЫ

```
уровень вложенности     9
ключ                    64 байта, то есть 32 знака кириллицы
строка исходного текста 1024 байта после преобразования
```

Заголовок глубже девятого уровня усекается, слишком длинный ключ
обрезается, слишком длинная строка теряет хвост -- и о каждом случае
выдаётся своя диагностика, см. ДИАГНОСТИКА.

Один предел диагностики иметь не может: огороженный блок не может
содержать строку, начинающуюся с ограждения. Оба написания -- один и
тот же маркер, поэтому первая же строка внутри блока, чьи первые
печатаемые знаки суть \`\`\` или ~~~, блок закрывает. Маркер в любом
другом месте строки -- обычный текст, чем и пользуется таблица выше.

### ПРИМЕР

Полный исходный текст из двух тем:

```
<!-- ident: MYLIB-01 -->

# COPY -- копирование файла

Копирует один файл в другой. Входной файл остаётся нетронутым.

Формат:

    COPY вход выход

## /LOG -- сообщать о каждом скопированном файле

Сообщает о каждом файле по мере копирования. По умолчанию /NOLOG.

## ПРИМЕРЫ

    $ copy a.txt b.txt
    $ copy /log a.txt b.txt
```

Трансляция и обращение к готовому:

```
$ vhelptran mylib.md /OUTPUT=mylib.hlb /IDENT=MYLIB-01
%HELP-I-CREATED, mylib.hlb created, 3 topics, 214 bytes of text

$ vhelp /LIBRARY=mylib.hlb copy /log
```

## /OUTPUT -- имя библиотеки

```
/OUTPUT=спецификация
```

Называет изготавливаемую библиотеку. По умолчанию это первый входной
файл с заменённым на .hlb типом.

Библиотека пишется во временный файл того же каталога и
переименовывается поверх целевого только после того, как последний
байт достиг файловой системы, поэтому неудавшийся запуск не оставляет
за собой недописанной библиотеки.

## /IDENT -- идентификация

```
/IDENT=строка
```

Заносит в заголовок библиотеки идентификацию длиной до пятнадцати
знаков. Она выдаётся по VHELP/LIST.

## /FACILITY -- корень библиотеки

```
/FACILITY=имя
```

Создаёт единственный ключ первого уровня, называющий объект, и
помещает всё, что содержат исходные тексты, уровнем ниже него.

Каталог пути поиска сливает темы первого уровня всех найденных
библиотек, поэтому то, что библиотека кладёт туда, видит вся
система. Библиотека, выносящая наружу свои глаголы -- SUBMIT,
DELETE, PURGE, -- кладёт их в пространство имён, общее со всеми
прочими библиотеками, где они сталкиваются с глаголами следующего
изделия и закрывают их либо закрываются ими. Один ключ на
библиотеку, называющий объект, и делает это пространство внятным:

```
  Information available:

  BATCH         DCL           HELP
```

Корень расходует один из девяти уровней вложенности, поэтому
исходный текст, занимающий все девять сам по себе, под корень не
помещается; тема, вышедшая за предел, сообщается как
%HELP-E-TOODEEP и прижимается к родительской.

Текст, стоящий перед первым заголовком, в библиотеке без корня идти
некуда, и он отбрасывается с %HELP-W-NOTOP. Под корнем ему есть
куда: он становится текстом самой темы объекта.

## /SORT -- упорядочение подтем

Квалификатор негируемый, и /SORT действует по умолчанию: подтемы
каждого ключа упорядочиваются по ключу -- именно так выглядит блок
"Additional information available" в HELP OpenVMS. /NOSORT сохраняет
их в том порядке, в каком они идут в исходном тексте.

## /EXTRACT -- восстановление исходного текста

Читает библиотеку и выдаёт её исходный текст на Markdown -- так же,
как LIBRARY/EXTRACT восстанавливает модуль на OpenVMS.

```
$ vhelptran /EXTRACT helplib.hlb /OUTPUT=helplib.md
$ vhelptran /EXTRACT helplib.hlb /KEY="HELPTRAN ФОРМАТ ИСХОДНОГО ТЕКСТА"
```

Первый проход восстановления неполон: пояснительный хвост заголовка
и маркеры разметки живут только в исходном тексте, в библиотеке их
нет. Зато со второго прохода круг замыкается -- извлечение,
трансляция и повторное извлечение дают тот же самый текст, и на этом
свойстве изделие проверяется.

## /KEY -- что именно извлекать

```
/KEY=путь
```

Извлекает только названную тему вместе с её подтемами. Путь -- это
ключи от первого уровня вниз, разделённые пробелами; ключ, сам
содержащий пробел, распознаётся целиком. Корень извлечённого
поддерева поднимается на первый уровень, поэтому получается исходный
текст, годный сам по себе.

## /LIST -- перечень изготовленной библиотеки

Читает библиотеку обратно после записи и перечисляет её дерево тем.
Заодно служит доказательством, что библиотека открывается и что её
контрольная сумма сходится.

## /HELP -- выдача синтаксиса команды

Выдаёт краткое описание обеих форм команды и завершается. Запрос
распознаётся как /HELP, /H, -help, --help или -h.

## ДИАГНОСТИКА

Транслятор сообщает -- но не отвергает -- о следующем:

```
%HELP-W-SKIPLVL   пропущен уровень заголовка, промежуточные
                  уровни достроены
%HELP-W-DUPKEY    две подтемы одного ключа названы одинаково
%HELP-W-LONGKEY   ключ длиннее 64 байт обрезан
%HELP-W-LONGLINE  строка длиннее 1024 байт потеряла хвост
%HELP-E-NOKEY     заголовок не содержит печатаемого текста
%HELP-W-NOTOP     текст стоит перед первым заголовком
```

# СООБЩЕНИЯ -- диагностика службы

Всякая диагностика записывается в формате OpenVMS

```
%HELP-<серьёзность>-<идентификация>, <текст>
```

и выдаётся на стандартную ошибку, но не на стандартный выход, который
несёт текст темы или исходный текст, полученный по /EXTRACT.

Серьёзность: S -- успех, I -- сведение, W -- предупреждение, E --
ошибка, F -- необратимое. Предупреждение означает, что работа сделана,
но что-то осталось за её пределами; ошибка -- что не сделана.

## ЧТЕНИЕ БИБЛИОТЕКИ

```
%HELP-E-NOTFOUND   темы с таким именем нет, назван весь путь
%HELP-E-NOTHLB     файл не является библиотекой справки
%HELP-E-BADVERS    библиотека иной версии формата
%HELP-E-BADCRC     контрольная сумма библиотеки не сходится
%HELP-E-TRUNCLIB   библиотека короче, чем сказано в её заголовке
%HELP-E-OPENIN     файл не удалось открыть
%HELP-E-READERR    файл не удалось прочитать
```

Библиотека, не прошедшая любую из этих проверок, не используется
вовсе. Ничего не чинится на месте: библиотека есть продукт сборки, и
ответ на повреждённую -- оттранслировать её заново.

## ПУТЬ ПОИСКА И КАТАЛОГ

```
%HELP-E-NOLIBS     на пути поиска нет ни одной библиотеки
%HELP-W-TOOMANY    элементов пути больше, чем вмещает каталог
%HELP-W-TOOMANYT   тем больше, чем вмещает каталог
%HELP-W-CACHERR    каталог кэша непригоден, кэширование отключено
%HELP-I-SYSCACHE   общий каталог записан
```

TOOMANY и TOOMANYT означают, что каталог неполон, и существующая тема
может не найтись. CACHERR не есть отказ запуска: просто каталог
строится заново каждый раз.

## ТРАНСЛЯЦИЯ ИСХОДНОГО ТЕКСТА

```
%HELP-I-CREATED    библиотека изготовлена
%HELP-I-DIAGS      сколько диагностик выдано при трансляции
%HELP-E-EMPTYLIB   в исходном тексте нет тем, ничего не создано
%HELP-W-NOTOP      текст стоит перед первым заголовком, отброшен
%HELP-E-NOKEY      заголовок без печатаемого текста, тема отброшена
%HELP-W-SKIPLVL    пропущен уровень заголовка, уровни достроены
%HELP-W-DUPKEY     две подтемы одного ключа названы одинаково
%HELP-W-LONGKEY    ключ длиннее 64 байт обрезан
%HELP-W-LONGLINE   строка длиннее 1024 байт потеряла хвост
%HELP-E-TOODEEP    заголовок глубже девятого уровня, усечён
%HELP-E-OPENOUT    выходной файл не удалось создать
%HELP-E-WRITERR    выходной файл не удалось записать
```

Предупреждение трансляцию не прерывает; библиотека изготавливается, а
итог выданного завершает запуск как %HELP-I-DIAGS.

## ИЗВЛЕЧЕНИЕ

```
%HELP-I-EXTRACTED  исходный текст записан
%HELP-E-CONFQUAL   /EXTRACT задан вместе с квалификатором другой формы
```

## КОМАНДНАЯ СТРОКА

```
%HELP-E-IVQUAL     значение квалификатора неприемлемо
%HELP-W-TOOMANYIN  входных файлов больше, чем вмещает команда
%HELP-W-TOOMANYQ   квалификаторов больше, чем вмещает команда
%HELP-W-TOOMANYW   слов в теме больше, чем вмещает команда
```

Каждый из трёх случаев сообщается однажды, сколько бы аргументов ни
было отброшено. Они существенны: команда, у которой пропал хвост,
иначе ответила бы о теме уровнем выше запрошенной и отчиталась бы об
успехе.

## ИСЧЕРПАНИЕ

```
%HELP-F-NOMEM      не удалось получить память
```

## ВНУТРЕННИЕ

Эти сообщают о неисправности самой службы, а не того, что ей дали, и
ни одно из них появляться не должно:

```
%HELP-E-QUEFAIL    ключ не удалось поставить в очередь при сборке библиотеки
%HELP-E-BADRUN     ключ называет текст за пределами кучи своей библиотеки
```

BADRUN возникает у библиотеки, чья контрольная сумма сошлась, то есть
указатель и куча противоречат друг другу -- оттранслируйте исходный
текст заново. О любом из двух сообщите.

# LIBRARY -- формат библиотеки справки

Библиотека справки -- плоский, самодостаточный файл только для
чтения, состоящий из трёх разделов: заголовка постоянного размера,
указателя ключей из записей постоянного размера и кучи, хранящей
текст каждой темы.

Записи ключей хранятся в прямом порядке обхода дерева тем, поэтому
всё поддерево ключа занимает непрерывный участок указателя. Именно
это превращает поиск по образцу, перечень и извлечение в обычный
последовательный проход по массиву.

## ЗАГОЛОВОК

Заголовок несёт сигнатуру, версию формата, смещения и размеры двух
других разделов, контрольную сумму CRC-32 по ним обоим, время
создания, идентификацию, заданную квалификатором /IDENT, и пометку
о том, чем и из чего библиотека изготовлена.

Сигнатура хранится в родном порядке байтов, поэтому библиотека,
перенесённая на машину с обратным порядком, отвергается, а не
читается неверно. Библиотека -- продукт сборки, а не формат обмена.

## КОНТРОЛЬНАЯ СУММА

Контрольная сумма покрывает указатель и кучу вместе. Она проверяется VHELP
при каждом открытии библиотеки; расхождение выдаётся как

```
%HELP-E-BADCRC, checksum error in ...
```

и библиотека не используется.
